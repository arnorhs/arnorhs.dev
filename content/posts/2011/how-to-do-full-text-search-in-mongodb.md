MySQL has had a pretty decent full text search engine in it's MyISAM storage engine and for some developers it's probably still a pretty big reason for sticking with MySQL (for some functionality at least). Somebody published [this link](https://www.mongodb.org/display/DOCS/Full%20Text%20Search%20in%20Mongo) to the The MongoDB blog [on Hacker News](https://news.ycombinator.com/item?id=2376349), just now, so I wanted to share it here. The article is actually from 2009 but it explains how to go about creating a full text search using Mongo. Even though this is a very simple example, it might help some people who rely on MySQL for some basic functionality. However, like the author points out, it doesn't have features like [text stemming](https://en.wikipedia.org/wiki/Stemming), ranking of queries matching n number of terms, bulk index building. More over it doesn't do what MySQL does so well for foreign character sets: match words like _ísland_ and _island_ as the same (a big \*win\* feature of MySQL in my books) But it would be interesting if somebody would implement that, even though just for fun. Maybe I should, but I'm not really in the mood atm. Check out the full article: [Full Text Search in Mongo - MongoDB](https://www.mongodb.org/display/DOCS/Full%20Text%20Search%20in%20Mongo).
